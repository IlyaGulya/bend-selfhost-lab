Erasure, evaluation order and calls are part of this boundary too

Lowering omits runtime-erased parameters while retaining required descriptor metadata. It lowers checked captures and pattern flow before target dispatch. Strict operations become ordered Lets; over-application is an initial call followed by unary Apply operations, not one oversized Direct call. A final returned Direct/Apply may become TailDirect/TailApply.

Local identities survive semantic substitution. A local initializer must not be re-evaluated for every reference merely because the checker stored a semantic value. Missing checked facts, unresolved references and unelaborated forms can fail lowering; failure is a diagnostic, not fabricated target code.

The executable constructor is Closure, not a fabricated BIR Lambda. DescriptorLambda belongs to the separate descriptor language. Tail calls are terminators, not operations. Blocks remain structured recursive trees; IDs do not make this an arbitrary CFG, SSA form or bytecode.

Affine use means at most one logical consumer use, not “the caller value is dead” or “freeing is automatically safe.” Atoms contain no nested operation tree; that does not make every target-level operand evaluation allocation- or effect-free.

Why descriptors survive when source types are no longer runtime expressions

Descriptor is a separate metadata language used for layout, display and host interoperation. For example, DescriptorRef retains a canonical key and argument descriptors; DescriptorArrow retains a quantity, domain and body. Erased formal positions may still matter to dependent metadata. Not every stored descriptor is already normalized.

The backend Program owns codes, declarations, constructors, families, type functions and an ending. SourceFile records may be loaded separately as passive foreign target code. They are not a checker source-arena field inside Program.

Scratch reuse is a lifetime mechanism

Used lengths rewind; allocated capacity remains reusable. Transient publication is a traversal into retained storage, not merely clearing a handle’s high bit. Epochs invalidate transient substitution-memo entries.

Ownership is not a memory benchmark

Pool growth may copy; occurrences and blocks remain recursive. None of these diagrams establishes zero allocation, a drop in RSS, constant memory or stack safety.

Handles, tapes, publication and validity limits

The arena’s six main pools are nodes, patterns, binders, words, naturals and names, with additional metadata and memo tables. Node handles use bit 31 for transient storage. Tape cursors also use bit 30 for reversal; that is not a universal node flag. Words, Names, Naturals and Quantities have start/count slices, but Names traverses a word tape of name IDs before resolving strings.

Source publication retains terms, types and recursively reachable occurrence data before transient rewind. An already-source handle can be reused; a transient object must have its contents published. The pinned implementation retains capacity, clears the 64-entry case-prefix table, advances the epoch and logically invalidates the 4096-slot substitution/publication memo rather than clearing every slot. These cache sizes are not term or binder limits.

CheckedProgram is constructible as a plain affine record. The carrier alone does not prove all handles valid or all checking obligations satisfied. The contracts distinguish producer discipline, dynamic checks and open semantic obligations; there is no complete BIR validator or mechanized proof of this whole pipeline.
