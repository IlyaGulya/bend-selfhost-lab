Self-hosted Bend compiler

Bend is a programming language. This compiler translates it to C or JavaScript. Written in Bend, it can also compile its own source.

Architecture details: official comparison, IR and ownership

An intermediate representation (IR) is the compiler’s internal description of a program. Both implementations already have IRs; this is not “IR versus no IR.”

The executable backend program is independent of the checker and source arena. This boundary alone does not establish a speed advantage.

Checking resolves names, types, affine uses and structural termination subject to explicit unsafe exceptions. Erased bindings are not runtime values. Failure returns a diagnostic, not a partly checked program. The front-end representation retains modules, signatures, scope metadata and checked occurrences.

Shared lowering makes erasure, captures, calls and pattern flow explicit. Backend blocks express bindings, branches, returns, tail calls and lexical regions; descriptors retain layout, display and host-interface metadata. Both targets still do analysis: C plans layouts, sharing and runtime tables; JavaScript plans continuation captures, frames, helpers and host adaptation. Neither is just a text printer.

The source pools use numeric handles and start/count slices. This is not all-flat or zero-allocation storage: checked occurrences and blocks remain recursive, and pool growth can copy storage. Scratch epochs invalidate transient substitution-memo entries. These mechanisms do not establish measured GC savings. The chunked execution protocol and JavaScript trampoline manage execution, not additional semantic IRs.

Measurement scope, workload and phase details

Three fresh serial processes per implementation, measured 7 November 2026, checked the same retained closure: 17 Bend modules and 35 foreign JavaScript files. Source-processing time excludes process launch and startup; code emission, external C compilation and a complete self-compilation cycle are not measured. The tiny closure demo above is a different input.

RSS is sampled across the owned compiler-command process tree including startup and teardown, not a phase-local heap or allocation count. Both roles exclude the guardian and measurement parent. One MiB is 1,048,576 bytes. Lower sampled RSS in this cohort does not establish universal memory use.

The official compiler interleaves template work differently. Only the combined source-processing boundary is comparable; native phase shares cannot support isolated official/native checker ratios. The ratio divides the two measured medians, not old receipts.

The native workload processed 1,690,863 bytes of Bend and 78,415 bytes of foreign JavaScript. Its source audit retains interfaces up to 50 arguments and a complete 66,793-byte resume dispatcher, with namespaces and foreign alternatives intact: no stubbed bodies, missing dependencies or AST replay. CPU-coverage analysis was inconclusive; this is not a universally representative performance proxy.

The phase ribbon uses native sample 3: parse 6.198936 s, expand 1.834936 s and check 19.672753 s, total 27.706625 s. It is an actual run, not summed phase medians. Parser-fuel setup took 1.318933 s inside parse, not a fourth phase: 136,000,000 cells over 17 modules. The 1,975,761 checking chunk advances count protocol resumptions, not source operations or machine instructions. These counts do not prove wasted work or predicted optimization savings.

The historical full-root validation covered 12,456 checked definitions and 13,050 validated events, with no excluded checks. Successive JavaScript images matched without normalization or output patches. The fixture executions supply separate behavioral evidence.

The front-end and backend laws are explicit contracts, not a mechanized proof of the whole pipeline. This evidence does not establish semantic preservation for every program, pure-C self-hosting, full C/JavaScript parity, GPU/WASM preservation or constant total memory use.

Full method: host, runtimes, guards and completion

The architecture describes the linked source snapshot. The timing comparison uses a digest-bound historical native executable built with diagnostic -O1 optimization, not a freshly built current-source compiler or the official default C optimization. Its current-source authentication wrapper rejects changed lexer and driver inputs. The measurement uses the documented raw check-only interface; it does not claim new build qualification. The official checker bytes match the retained kernel.

Host and date

Sampling order
Three fresh serial process pairs: official/native, native/official, official/native. No process reuse, profiler, forced garbage collection or discarded warmups. Filesystem and OS caches were not flushed.
Timed operation
Official: load/parse/expand + check. Native: parse + expand + check, including eager parser-fuel setup. Startup, emission and external C compilation excluded. The headline is the ratio of source-processing medians.
Official runtime
Node 23.11.0, V8 12.9.202.28-node.14; --experimental-strip-types --max-old-space-size=6144 --max-semi-space-size=128. Worker limits: 6,144 MiB old generation, 128 MiB young generation and 256 MiB stack. Node may use helper threads.
Native runtime
Cached diagnostic -O1 split-LLVM executable; one compute thread, GPU off: +RTS --threads 1 --gpu off --RTS. Each run recorded 17 eager parser-fuel rows of 8,000,000 cells and ordered parse, expansion and checking phases.
Memory and guards
Bun 1.4.3 launches a guardian sampling the owned compiler-command process tree every 10 ms. Official includes Node main process and worker; native includes its process. Bun launcher, guardian and cohort parent are excluded. RSS and physical-footprint stop guards: 8,192 MiB each; 600-second timeout, 1-second termination grace. These are sampled stop guards, not hard allocation quotas or exact peaks.
Completion
All six runs passed the guards. Official covered the 52-file input map, 2,420 definition bodies and 2,954 validation events, with no holes or unchecked bodies. Native returned CheckSuccess for all 17 modules. No checks were excluded or outputs patched. Foreign JavaScript belongs to the retained input closure; its emission and execution are not timed.
Input identity
Inputs, compiler/runtime artifacts, manifests, receipts and protocol helpers were rehashed before and after every sample and the cohort. Bounded 64 KiB hashing buffers were in the unmeasured parent. Sorted source-tuple SHA-256: 2555918b9caf261ab6a85fad8ef8fb132a87d9c835b77ee3a86cdefaed1dca01.

Separately recorded guardian elapsed medians: 3.082 s official (2.551–3.660 s), 28.154 s native (25.960–34.264 s). These include startup and teardown and are not the headline boundary.
